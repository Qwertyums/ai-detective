# AI Detective

Лабораторная работа № 6 по автоматической обработке текстов. Полностью вымышленное досье о сбое на турнире: 10 документов, 5 151 слово, 40 атомарных утверждений, 12 вопросов шести типов. По умолчанию запросы выполняются **за счёт подписки ChatGPT** после входа через официальный OAuth. Модель выбирается из списка доступных аккаунту и остаётся одной для всех режимов серии. Отдельный API-биллинг доступен только при явном выборе. Архивные D08 и D10 создают тематически похожий шум.

## Запуск в Windows PowerShell

Из корня репозитория, Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
# Для подписки API-ключ не нужен. Войдите через кнопку Continue with ChatGPT.
.\.venv\Scripts\python.exe -m src.data_validation
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m streamlit run app.py
```

## Подключение подписки ChatGPT

1. Запустите Streamlit и выберите «Подписка ChatGPT» в разделе «Источник лимитов».
2. Нажмите **Continue with ChatGPT**, затем **Открыть вход в ChatGPT**. Приложение заранее запускает callback на 127.0.0.1; ссылка действует 10 минут.
3. В системном браузере войдите в свой аккаунт и разрешите **Use your ChatGPT plan**. Только вход без этого разрешения не даёт права выполнять запросы.
4. После возврата из браузера нажмите **Проверить вход**. Аккаунт и разрешения проверяются до активации сессии. Если доступ к тарифу не предоставлен, используйте кнопку «Разрешить использование тарифа».
5. Выберите модель подписки. Список получается после входа; после перезапуска приложения нажмите «Обновить список моделей». Используйте одну и ту же модель для всей серии A/B/C.
6. Кнопка «Управлять лимитами ChatGPT» открывает Settings → Usage. Используются общие лимиты подписки. При их исчерпании приложение не переключается на платный API.

Доступ зависит от тарифа, аккаунта и разрешений OpenAI; успешное подключение подтверждается фактическим завершением запроса. Поддержка входа предназначена для локального приложения в Windows. Сессия хранится в `.chatgpt-auth/session.bin`, зашифрована Windows DPAPI текущего пользователя и исключена из Git. Токены не передаются в Streamlit-виджеты, результаты, URL запросов к API или журналы. Установка имеет постоянный host ID; каждая регистрация — отдельный client ID и проверенную личность. Аккаунты с одинаковым email не объединяются. Refresh выполняется под межпроцессной блокировкой с сохранением замены refresh-токена.

Выход пытается отозвать сессию на сервере и удаляет локальные токены, сохраняя регистрацию для повторного входа. Если отзыв не подтверждён, приложение явно сообщает об этом; отключите его в настройках ChatGPT. Для добавления ещё одного аккаунта выберите «Добавить аккаунт» и выполните новый вход.

.\.venv\Scripts\python.exe scripts/chatgpt_login.py login

Для выбора сохранённой регистрации: `chatgpt_login.py select --profile PROFILE_ID`. Её ID показан в `status`. При незавершённом обмене кода выданная регистрация сохраняется, но не активируется: повторите `login --profile PROFILE_ID`.

### Отдельный API-биллинг

Это альтернативный режим. Выберите «OpenAI API — отдельный биллинг» либо задайте `.env`:

```dotenv
OPENAI_AUTH_MODE=api_key
OPENAI_API_KEY=ваш_ключ_OpenAI_API
OPENAI_MODEL=gpt-6-luna
```

Для подписки используйте `OPENAI_AUTH_MODE=chatgpt` (значение по умолчанию). Переменные окружения имеют приоритет над `.env`. После изменения `.env` перезапустите приложение. Ключ и файл `.env` не попадают в результаты или Git. Без API-ключа блокируется только режим отдельного API-биллинга. Веса и CUDA не нужны.

## Режимы и воспроизводимость

- A: все документы в порядке `documents.jsonl`, рядом с каждым — индекс цитат с claim_id. Индекс нужен для единого формата ответа и метрик доказательств. Это дополнительный служебный объём, который включается в число входных токенов.
- B: BM25 выбирает top-15 по текстам утверждений и цитатам. Нормализация — Unicode-слова и нижний регистр, без морфологии; равные оценки разрешаются по claim_id.
- C: тот же набор и те же тела записей, что в B; меняются группировка по ветвям и порядок. Внутри ветви сортировка по времени события, неизвестное время в конце.

Путь p=3: тип источника, статус, временной интервал. Исключения получают логическую категорию 2. Событие — интервал от 17:03 до 19:22 включительно 14 марта 2026, часовой пояс +03:00. Время публикации не подменяет время события. Числовой код `a0 + 3*a1 + 9*a2`; расстояние определяется длиной общего префикса, а не разностью кодов.

Общий промпт находится в `prompts/system_prompt.txt`. В режиме подписки используется публичный Responses API, OAuth access token, `store=false`, `stream=true`, `instructions` вместо системного сообщения в input. Запрещённые этим маршрутом max_output_tokens, truncation, temperature, top_p, conversation и previous_response_id не отправляются. Ответ считается завершённым только после response.completed; response.failed, response.incomplete, отказ и оборванный поток сохраняются как ошибки. Для gpt-5/gpt-6 используется reasoning effort low.

В режиме API-ключа сохраняются strict JSON Schema, максимум 2048 выходных токенов, store=false, truncation=disabled. Для обеих авторизаций таймаут 60 секунд и скрытые повторы SDK отключены. Имя выбранной/фактически ответившей модели, способ авторизации, параметры, промпт и состав контекста записываются в результат. Для подписки сохраняется только необратимый идентификатор регистрации, без email и токенов; серии разных аккаунтов и способов оплаты не смешиваются.

Structured Outputs требует все поля ModelOutput, включая nullable-поля, и ограничивает evidence_ids доступными утверждениями. Дополнительно Pydantic проверяет both, insufficient, диапазон confidence, идентификатор вопроса и доступность ссылок. Структурная проверка не доказывает правильность объяснения; её проверяет человек. Ошибки сети, авторизации, квоты, отказ модели и незавершённый ответ не подменяются логическим insufficient.

При нарушении локальных логических ограничений выполняется один запрос на исправление с тем же контекстом. Скрытые автоматические повторы SDK отключены. Сохраняются обе попытки, их ответы и ошибки; входные, выходные, кэшированные и reasoning-токены берутся из API usage и суммируются. Время измеряется вокруг каждого сетевого запроса и также суммируется. Старые результаты локальной модели остаются в results/runs и не смешиваются с новыми сериями благодаря разным модели и настройкам.

## Эксперименты

В режиме подписки subscription_sharing_usage_limit_exceeded и subscription_sharing_usage_unavailable отправляют к лимитам ChatGPT; повторного запроса за API-деньги не будет.

В режиме API-ключа при HTTP 429 смотрите код в сообщении и разделе «Диагностика API». `insufficient_quota` относится к доступной квоте, `credit_balance_exhausted` — к кредитам, `project_spend_limit_exceeded` и `organization_spend_limit_exceeded` — к лимитам расходов. Повторы запроса не устраняют эти причины. `rate_limit_exceeded` и `slow_down` — временные ограничения: снизьте частоту и соблюдайте Retry-After. Если сервер не уточнил код, приложение не объявляет причиной автоматически нулевой баланс. Диагностика сохраняется в api_metadata; тело ошибки и секретные заголовки не записываются.

```powershell
# Сначала выполните chatgpt_login.py login и проверьте доступность модели.
# Все 12 вопросов в A/B/C: 36 запросов
.\.venv\Scripts\python.exe scripts/run_experiments.py --suite baseline --resume

# База и подготовленные стресс-сценарии: 144 запроса,
# непроверенные человеком сценарии выполняются без расчёта метрик
.\.venv\Scripts\python.exe scripts/run_experiments.py --suite all --exploratory --resume

.\.venv\Scripts\python.exe scripts/summarize_results.py
```

Для проверки одного запроса доступны `--question Q1 --mode B`. Через `--model` задаётся модель из каталога аккаунта, через `--provider chatgpt` или `--provider api_key` — явный способ авторизации. Каждый запуск сразу сохраняется отдельным JSON в `results/runs/`. `--resume` пропускает уже сохранённую попытку, включая невалидный ответ; для намеренного повторения уберите этот флаг. После ошибки окружения пакет прекращается. После ошибки ответа модель продолжает следующие вопросы; ошибка сохраняется.

Имена результатов содержат московское время начала запроса, вопрос, режим, сценарий, источник лимитов и короткий уникальный ID: `2026-10-28_17-30-00_MSK_Q1_B-bm25_baseline_chatgpt_ab12cd34.json`. Обозначения режимов: A-full, B-bm25, C-padic; сценарии: baseline, shuffle, remove-C17, contradiction. То же имя используется при скачивании из интерфейса. Старые UUID-файлы можно переименовать без изменения JSON: `python scripts/rename_results.py` (предварительный просмотр: `--dry-run`).

Сводка и интерфейс сравнивают последние попытки только полных троек A/B/C с совпадающими данными, вопросом, сценарием, моделью, параметрами и промптом. Разные серии не смешиваются. Базовые и стресс-условия отображаются отдельно. Для валидных ответов рассчитываются accuracy, evidence precision/recall/F1, counterevidence recall, распознавание both/insufficient и доля уверенных утверждений при insufficient (порог 0.8). Ошибки показываются отдельно; дополнительно есть accuracy по всем попыткам, где ошибка считается неуспехом. Приведены реальные токены и время, изменение статуса/ответа, Jaccard evidence_ids и соответствие ожидаемому статусу после вмешательства. Калибровка confidence доступна через `analyze_confidence_calibration`.

## Ручная проверка

Условие требует проверки эталонов всей командой и ручной проверки стресс-вмешательств. Они не считаются выполненными автоматически. Откройте `data/WORKING_TRUTH.md`, вопросы и `data/STRESS_REVIEW.md`. Полные копии доступны в `results/scenarios/`. В интерфейсе можно скачать исходный и изменённый состав и сохранить свою проверку с именем.

Командная строка для человека, действительно проверившего конкретный сценарий:

```powershell
.\.venv\Scripts\python.exe scripts/review_cases.py --case R_Q3 --reviewer "Имя участника"
# Только после проверки содержания:
.\.venv\Scripts\python.exe scripts/review_cases.py --case R_Q3 --reviewer "Имя участника" --approve
```

`--case all` допустим только после проверки всех сценариев. Проверка привязана к хешу данных, вопроса и вмешательства: после изменения содержания требуется новая проверка. Уже сохранённые непроверенные ответы задним числом не получают оценку; после проверки выполните новые прогоны. Не изменяйте review-поля от имени несуществующих участников.

Стресс-перестановка подготовлена для всех 12 вопросов с seed=42; удаление — для всех 12 вопросов; добавление конфликтующего источника — для всех 12. У Q11 и Q12 конфликт в посылке не устраняет неизвестность личности/вектора, поэтому ожидается сохранение insufficient. Всего 36 стресс-сценариев × 3 режима = 108 стресс-запусков; вместе с 36 базовыми — 144. Для удаления у Q9/Q10 ожидается entailed после удаления одной стороны конфликта, у Q11/Q12 сохраняется insufficient. Это проектные эталоны, требующие ручной проверки; редакторские пересказы конфликта у Q9/Q10 особенно важно проверить на утечку удалённой позиции. Во всех случаях меняется один фактор. B/C после перестановки могут остаться полностью одинаковыми: это ожидаемый контроль детерминированного retrieval.

## Сдача

`AI_LOG.md` описывает фактические эпизоды текущей доработки, `CONTRIBUTIONS.md` — известный вклад и незаполненные сведения команды, `DEMO.md` — сценарий демонстрации до 7 минут. `report.md` и `report.pdf` отражают только сохранённые результаты. Статус реальных запусков проверяйте по `results/summary.json`, а не по наличию функции в коде.

Для пересборки PDF:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-report.txt
.\.venv\Scripts\python.exe scripts/build_report.py
```

Служебные `scripts/prepare_dataset.py` и `scripts/prepare_stress.py` детерминированно пересоздают авторские данные и сценарии. Они перезаписывают соответствующие файлы, а подготовка сценариев по умолчанию сбрасывает их ручные проверки. Флаг `prepare_stress.py --preserve-reviews` сохраняет проверки только для неизменённых определений; после изменения исходных данных действительность проверки всё равно определяется хешем. Не запускайте их после ручной правки без сохранения своей версии. Рабочая истинная история не передаётся модели.

Документация: https://developers.openai.com/siwc/token-sharing-open-source и https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations . Секреты и файлы окружения исключены из Git.


### Просмотр неполных серий

Раздел «Сохранённые результаты» показывает метрики доступных запусков по всем вопросам выбранной серии и условия, даже если выполнен только один режим. Для каждого эксперимента и режима используется последняя попытка. Таблица недостающих режимов поясняет, что требуется для сравнения A/B/C. Раздел «Сравнение полных троек A/B/C» и основные поля metrics/stability/calibration в summary.json сохраняют строгое сравнение; поля available_metrics/available_stability/available_calibration показывают доступные данные, coverage — покрытие режимов. Непроверенные сценарии не получают оценки. Заголовок последнего запуска в сессии относится к одному ответу и не ограничивает общую сводку.
